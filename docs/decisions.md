## Technical decisions (Phase 1)

| Topic                  | Decision                                                                                               | Reason                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Migration tool         | Knex migrations in `database/migrations`                                                               | Version-controlled, reversible, same driver as the app                                                                       |
| Dates                  | Leave dates are `DATE` columns returned as `YYYY-MM-DD` strings; event times are UTC                   | Prevents timezone shifts moving a leave day                                                                                  |
| Append-only data       | `balance_ledger`, `audit_log` and `approval_actions` have database triggers refusing UPDATE and DELETE | Ledger and history cannot be altered, even by a mistaken query                                                               |
| Exactly-once deduction | Unique key on (source, entry type, leave type, leave year) in the ledger                               | A second approval attempt fails at the database even if application checks are bypassed                                      |
| Accrual idempotency    | Unique key on (employee, leave type, entry type, period)                                               | A monthly job re-run cannot accrue twice                                                                                     |
| Manager role           | Derived from the reporting line (anyone who is a manager), not a stored role                           | Cannot drift out of step with the org structure                                                                              |
| Environment isolation  | Config refuses a test run unless `DB_NAME` ends in `_test`, and refuses `_test` databases elsewhere    | Fixtures can never reach a real database                                                                                     |
| Migration account      | Optional `MIGRATION_DB_USER`; app account can be limited to data access                                | Least privilege in production                                                                                                |
| OIDC library (D18)     | `openid-client`                                                                                        | Full OpenID Connect checks (signature against Entra's keys, issuer, audience, nonce, state, PKCE) in one well-tested library |
| Session store          | Own small store on the existing Knex connection                                                        | The common express-mysql-session package bundles an old, vulnerable mysql2                                                   |
| Linking accounts       | Refused sign-ins are recorded and listed for HR                                                        | HR links people without copying Object IDs; identity is still matched only on tenant + object ID                             |
